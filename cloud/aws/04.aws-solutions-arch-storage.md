## EBS: Elastic Block Store volumes
Elastic block store (EBS) are network devices you can attach to machines. It has the following attributes:

* Bound to specific AZ.
* It persist data even after their termination, but can be deleted-on-terminate an EC2 instance.
* Can be mounted only to one instance at a time, at CCP level.
* Detached and re-attached to a new instance very quickly (failovers).
* Have provisioned capacity, and you are billed by this (this can be increased).
 

### EBS Snapshots
Snapshots (or backups) can be created from an EBS volume.

Because EBS are bound to a specific AZ, a snapshot is required to move a volume across AZ (disaster recovery strategy).

Snapshots can be used also to do backups, there are different **storage tiers**:
* EBS Snapshot Archive: 75% Cheap than regular EBS storage. 24 to 72 hours for restoring.
* Recycle bin: With specific retention rules (1 day to 1 year)
* Fast snapshot restore (FSR): Expensive

### EBS volume types
Different types (depending on the technology, size and IOPS):

* gp2/gp3 (SSD): general purpose & balanced price.
* io1/io2 Block Express (SSD): Highest performance SD volume.
* st1 (HDD): Low cost HDD volume. Throughput optimized
* sc1 (HDD): Lowest cost HDD volume. Archive data

The cost is linked to the volume type. only gp2/gp3 and io1/io2 can be used as boot volumes.

### EBS multi-attach
io1/io2 EBS volume types can be attach to multiple EC2 instance in the same AZ.

This can be used for achieve higher application availability in clustered applications.

Up to 16 EC2 instances a at time & require cluster-aware filesystem.

### EBS encryptation
Handled transparently by EBS & EC2. All the traffic between this is encrypted by default (KMS keys - AES-256)
This encryption has minimal impact on latency.

## AMI: Amazon Machine Image
Is a customization of an EC2 instance. Is usefull to re-use OS dependencies.
To create it, you need to setup & stop an EC2 instance and then build the AMI.
They are binded to a specific AWS region.

Golden AMI is an image with all the dependencies of an application/use case. For dynamic configuration, bootstraping with user data can be used (or even an hybrid solution).

## EFS: Elastic File System

NFS (using POSIX) that can be mounted on many EC2 across multi-AZ. Is used for content management, web serving, data sharing use cases.

It has the following properties:
* It is highly available.
* Uses security groups to control the access.
* Only compatible with Linux based AMI.
* Encrypted at rest using KMS.
* No capacity planning, pay-per-use.

There are different performance & storage classes for EFS:
1. EFS Scale: Petabye-scale network
2. General purpose(default): latency-sensitive use cases
3. Max I/O: Higher latency
4. Bursting mode: Scale the throughput with the amount of storage.
5. Provisioned: Set throughput
6. Elastic: Auto scale throughput

For the storage tiers, exists different tiers that can be used with lifecycle policies
1. Standard
2. Infrequent access (EFS-IA)
3. Archive

Availability and durability
* regional(default/standard): Multi-az
* One-zone: Cost saving but bind the EFS to one AZ.

## S3 Bucket storage
Infinitely scaling storage (used as backbone of the cloud). Buckets (directories) to store objects (files) at region level. 

Max 50 TB object size, multi-part upload if file size > 5 GB.

S3 has a key for each object: prefix + object name. Also it has a metada, tags and a version id.

It covers multiple use cases:
* Backup & storage
* Disaster recovery
* Archive
* Hybrid cloud storage
* Host media/applications
* Data lakes & big data analytics
* Static websites hosting

The naming of the buckets must have a globally unique name (across regions/accounts).

### Security / Bucket policy
By default, public access is on to prevent data leaks.

The access to the objects can be defined via user-based(IAM policies/roles) or resource-based policies (Bucket policies/Object ACL/Bucket ACL/cross-account policies).

#### Object encryption
Encryption keys are another way to add security to the buckets/objects, there are different encryption methods:

A) Server-side encryption:
* S3 Managed keys: Enabled by default for new buckets & new objects
* KMS: The key is user managed (AWS KMS). CloudTrail can audit the usage of the keys. This implies API calls to AWS KMS quota
* C: Keys are managed outside AWS (enforced HTTPS).

B) Client-side encryption: Clients must encrypt data & de-encrypt data outside AWS

In-flight encryption (SSL/TLS) is used by S3 using HTTPS endpoint (mandatory for SSE-C)

Bucket policies can enforce object encryption.

#### CORS (cross-origin resource sharing)
Web browser security mechanism. It needs to be enabled at the bucket level to be used.

#### MFA Delete
Multifactor authentication to dangerous operations (only the root account can enable this). 

#### Access logs
Audit purpose. The data can be analyzed using data analysis tools or AWS Athena.

#### Pre-signed URLs
The user that gets that URL inherit the permission of the user that generated the URL (created via console, CLI or SDK).

### Versioning
It requires to be enabled at bucket level. It create a version of the files based on the key.

Useful to roll back & protec against unintended deletes.

### Replication
It requires to have versioning enabled. Copy is ASYNC. 

It will replicate the new objects; to replicate all the existing objects you need S3 Batch replication.

Two flavors: Cross region replication(CRR) or Same region replication(SRR).

### Storage classes & rules
Durability of an object (11 9s) defines the expected time to lose an object(11 9s % for all S3). Availability measures how readily a service is (99.99% for gp S3).

S3 analytics is updated daily and add recommendations for standard & Standar IA

Several classes, according to different uses cases:
* General-purpose
* Standard-infrequent: Disaster recovery & Backups
* One-zone infrequent: In a single AZ & data is los when AZ is destroyed. Secondary copies or data you can recreate.
* Glacier: Low-cost object storage. Used for archive/backup.
  * Instant: milliseconds retrieval.
  * Flexible: 1-5mins/3-5 hours/5 to 12 hours -> Free 
  * Deep: Long term storage 12/48 hours. Lowest cost and 180 storage duration.
* Intellingent tiering: Move objects auto between access tiers.
  * Frequent
  * Infrequent
  * Instant
  * Archive
  * Deep archive

Lifecycle rules can be used to transition objects from one storage class to others.

Expirations actions can be used to delete objects after some times & multi-parts upload.

### Express one-zone
High-performance for a single AZ, using a directory bucket.

### S3 requester pays
The bucket owner pays for all S3 storage & data transfers associated costs(networking).

With requester pays, the networking cost is paid by the requester(must not be anonymous).

### Event notifications
Always that certain events happens (objectCreated, ObjectRestored) a S3 events happens. It can be cached by Lambda funtions/sqs/sns/Amazon EventBridge(with advance filtering options).

It requires IAM permissions/policies for each service (no EventBridge)

### Performance
S3 automaticaly scale to high request rates w/ latency 100-200ms & can achieve 3,500 PUTS/COPY/POST/DELETE or 5,500 GET/HEAD requests per second per prefix.

There are strategies to increase performance:

* Multi-part upload: paralelize uploads (recommended for size > 100MB, required if size > 5GB)
* Transfer acceleration: Increase download/upload transferring a file to an AWS edge location.
*  Byte-range fetches: Parallelize downloads (GETs) by specific byte ranges.

### Batch operations
Bulk operations on S3 objects with a single request, doing:

* Modify object metada/properties
* Encrypt un-encrypted objects
* Restore objects from S3 Glacier
* Modify ACL
* Invoke lambda functions for custom actions

It helps managin retries, track progress, send completion notification, generate reports. 

S3 inventory will generate a list objects and then Athena (filter) that will be used by the S3 Batch operation (+ user parameters) in order to generate the processed objects. 

### S3 Storage Lens
Understand, analyze and optimize storage across AWS organization.
It aggregates data & analyze (create a dashboard) and visualize the insights. Can be configured to an S3 bucket(csv, parquet)

It has available different metrics:
* Summary metrics (used bytes)
* Cost-optimization metrics
* Data-protection metrics: versioning enabled? cross-region replication?
* Access-management metrics:
* Event-metrics: Events configured
* Performance metrics: S3 transfer acceleration
* Activity metrics:
* Status code metrics: HTTP status code.

There are a free and a paid metrics.

### S3 Glacier Vault lock & object lock
Write once - read many (WORM) model to prevent objects from being deleted/overwritten.

**S3 Glacier Vault Lock** applies a vault lock policy to a Glacier vault (archive-level).
- The policy (IAM-like JSON) defines compliance rules, e.g. "deny delete if archive age < 1 year".
- Two-step process: **Initiate** (starts a 24h validation period) → **Complete** (policy becomes immutable).
- During the 24h window, you can abort via `AbortVaultLock`. After completion the policy is **locked forever** — not even root can change it.
- Use case: regulatory compliance (SEC Rule 17a-4, etc.).

**S3 Object Lock** works on S3 buckets (objects), requires versioning enabled.
- Applied per-object or as a default bucket setting.
- **Retention modes:**
  * Compliance: Object can't be overwritten/deleted & the retention mode **cannot** be changed by anyone (including root).
  * Governance: Special users with `s3:BypassGovernanceMode` permission can change retention or delete the object.
- **Legal hold:** No retention period — prevent deletion indefinitely until explicitly removed by a user with `s3:PutObjectLegalHold` permission.
- Unlike Vault Lock, Object Lock retention periods and holds can be modified/adjusted (unless locked in Compliance mode).

### Access points
Set policies/access on front of the access of the buckets. Simple way to manage security in buckets.

Each access point has its own DNS name + access policies

#### Object Lamdba
Change the object content before is retrieved by the caller app (convert data/redacting personally information/watermarking images on-the-fly).

It uses a Lamdba function through a Lambda access point.

## CloudFront (CDN)
Content Delivery Network. Using hundreds of points of presence globally (edge locations, caches) improves read performance, as the content is cached at the edge.

Several origins (backends) can be used by CloudFront:
* S3 bucket: Secure access via (OAC), used for distributing files
* VPC origin: For applications hosted in VPC private subnets
* Custom origin via HTTP: S3 websites or any public HTTP backend (public ALB)

Content is updated after the TTL expiration, but the user can enforce an entire/partial cache invalidation (CloudFront invalidation).

Content could be geo-restricted using an Allowlist or BlockList. The country is determined using a 3rd party geo-ip Database.

It provides DDoS protection via AWS shield.

## Global Accelerator
Minimize latency for global applications using Anycast IP (2 for application) + using AWS internal network. It provides consistent performance & provides health checks for global applications.

It provides DDoS protection via AWS shield.

It works with EC2, ElasticIP, ALB, NLB, public or private.

## Snowball
Highly-secure, portable device to collect & process data at edge and migrate data into and out of AWS. Helps migrate Petabytes of data.

Storage and compute optimize flavours (physical devices). Use case for edge computing as well.

## FSx
Launch 3rd party high-performance file systems on AWS (managed service).

## Storage gateway
Hybrid cloud paradigm. This gateway provides a bridge to access AWS storage from the on-premises data on the cloud. This gateway can run on-premises or in an EC2 instance.

Useful for disaster recovery, backups & restoring.

Different flavours for this bridge:
* S3 file gateway: Using NFS/SMB + HTTPS to connect into the S3 bucket.
* Volume gateway: Using iSCSI protocol backed by S3 + EBS snapshots (backup volumes)
* Tape gateway: Using iSCSI-Virtual tape library. Uses Glacier to store the data.

## Transfer family
Fully managed service for file transfers into and out of Amazon S3 or EFS. It supports FTP, FTPS and SFTP.

It require an IAM role for S3 or EFS + User authentication via AWS or some 3rd party.

Usefull for share files, public datasets.

## DataSync
Service to move a large amount of data to and from on-premises (agent required) or AWS.

Will schedule sync data to S3 / EFS / FSx. Will preserve the metadata (NFS POSIX).
