## Private vs Public vs Elastic IP

Formally, internet is a network of networks where we define:

* Private @: Internal IP address, uses NAT + gateway to access WWW.
* Public @: Unique IP address across all WWW.

AWS introduces the concept of elastic IP @, which is an @ you own as long as you don't delete it. In a AWS account you can only have up to 5 elastic IPs (can be increased).

It is a bad decision to use elastic IPs in some design, instead use random IP @ + DNS register or a load balancer.

## Placement groups

Strategy to place the EC2 instances:

* Cluster: low-latency group in the same AZ. ~10 Gbps BW.
* Spread: Instances placed in different AZ and different hardware. Limited to 7 instances per AZ per placement group. Designed for critical applications
* Partition: Each partition represents a rack on AWS. Up to 100 EC2 instances. Designed for big data application & partition-aware software.

When a EC2 instance is launched, the placement group can be selected.

## Elastic Network interfaces (ENI)
Logical component in a virtual-pc that represents a NIC. ENIs can be attached on-the-fly to EC2 instances but are bounded to a specific AZ.

A ENI can have the following attributes:

1. Primary IPv4 and one or more secondary IPs
2. One Elastic IP per private IP
3. One public IP
4. One or more security groups
5. A MAC Address.

Used to manage failures with instances
