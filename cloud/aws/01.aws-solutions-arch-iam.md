Users are the baseline of the cloud and are a security mechanism. You must create users instead of using the root account. 

The grant-least-privilege principle is the rule of thumb for defining users and permissions. The permissions should be defined to the groups as a good practice but inline policies can be defined for a unique user.

Groups can't contain other groups.

### IAM policies

JSON file is used to define policies, which consists of:

1. Version and policy id
2. List of statements
    1. ID
    2. Effect: Allow/Deny.
    3. Principal: User/Group/role to which this policy applies.
    4. Action: Actions this policy allows/denies
    5. Resource: List of resources for this policy
    6. Condition (optional)

Policies can be defined using the AWS console with an interactive form.

### IAM Password policies

The password policies can be defined from IAM > Account settings. There we can define a policy of which kind of password (length, specials chars) is required in our system for the users.

MFA (Multi-factor authentication) must be set at least for the root/admin accounts. This can be set using IAM dashboard > Account settings.

### AWS access keys 
Used for CLI and SDK. Private key for every user.

### IAM Roles for services
IAM roles are supposed to be used by AWS services, not by physical people.

### IAM security tools
Several options can be used to check the IAM security of your system:

* IAM Credential report
* IAM Access advisor (last accessed)

### IAM summary & Best practices
* 1 physical user = 1 AWS user.
* Assign users to groups & assign permissions to groups.
* Create a strong password policy & enforce the use of MFA.
* Create and use Roles for AWS services make request on the users behalf.
* Access keys for CLI/SDK.
* Audit periodically users permissions using the tools.

## AWS Organizations
Manage multiple AWS accounts. It provides cost savings and share reserved instances.

It is based by organizational units (OU), managed by the management account (kind of a root account) which seats under the Root OU.

We can define also Service Control Policies (SCP), which restrict users and roles.

Tags are usefull to audit usages.

### AWS IAM Identity center
Service for single sign-on for all your AWS accounts, Bussines cloud applications or SAML2.0 apps.

It requires to be linked with the user identities center or use the IAM Identity center of AWS.

### AWS Control tower
Set up and govern a secure & compliant multi account AWS environment.

Preventive guardrail -> SCPs
Dectective guardrail -> AWS Config
