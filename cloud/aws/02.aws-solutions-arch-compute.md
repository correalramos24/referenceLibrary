## EC2 virtual machines renting
Need to select the size with the following parameters:

* OS : Uses AMI (Amazon Machine image)
* CPUs cores
* Memory RAM
* Storage
    * Network (EBS & EFS)
    * Hardware (EC2 instance store)
* Network
    * NIC, Address
    * Firewall: Security group
* EC2 User data - bootstrapping: Boot execution script

By default, ec2-user is the default username. AWS web UI provides EC2 instance connect, a ssh client to connect to an EC2 instance.

## EC2 Instance types
Comparison between instance types can be checked [here](aws.amazon.com/ec2/instance-types) or [here](https://instances.vantage.sh/)

The instance type follow a common naming convention: {Instance class}{Instance generation}.{Instance size}

Several instance type are listed, the most used are:

* General-purpose (t2.micro): Good balance between Compute/Memory/Networking
* Compute-optimized(c5): Compute-intensive tasks(HPC)
* Memory optimized(r6/x1): Memory-intense tasks (in RAM databases)
* Storage-optimized(i4/d1/h1): Storage focused tasks.

### EC2 Hibernation
With hibernation the in-memory state is preserved into the EBS root volume.

### EC2 Instance storage
Hardware disks (faster than EBS) exists for better I/O performance as EBS are network drives.

There are ephemeral storage, linked to the EC2 instance. There are designed for cache/buffer/scratch data/temporary content.

## Security groups
Fundamental network security on AWS. Contain allow groups rules to our EC2 instances to control the inbound and outbound network traffic.
The security group lives "outside" the EC2 instance and can be re-used inside the same region. Timeouts are caused by the security groups and deny responses are caused by the applications.

They regulate:
* Access to ports
* Auth IP ranges (IPV4 & IPv6)
* Inbound networks from other instances
* Outbound traffic to another instances

By default all inbound traffic is blocked & all the outbound traffic is authorized.

### Classics ports

List of useful ports:
* 21 : FTP
* 22 : SSH & SFTP
* 80 : HTTP
* 443: HTTPS
* 3389: RDP (Remote Desktop Protocol)

## EC2 Instance roles

Never enter IAM access keys into the virtual machine, use IAM roles instead. Roles can be attached using the AWS Console.

## EC2 Instance purchasing options

There are different options to rent virtual machines:

1. On-demand : Pay per second, highest cost. Recommended for short-term workload
2. Reserved instances (~70%): 1-year/3-year rent & upfront payment. This provides more discounts. Convertible reserved instance allow to change the OS.
3. Saving plans (~70%): Commit to certain type of usage. 
4. Spot instances (~90% discount): Set the max price you want to pay. Not able for critical jobs/databases as you can "lose" the instance at any point if the price is exceeded.
5. Dedicated hosts (most expensive): Physical server with EC2 instance fully dedicated. Can pay on-demand or reserve. Bring your own license use case.
6. Dedicated instances: No exclusive physical reservation. 
7. Capacity reservations: Reserve on-demand instances capacity.

### EC2 Spot instances
Define the max spot instance price and get them as long of current spot price < max. There's a grace period to close the instance (2 minutes).

The spot price depends on the whole system demand. We can request a spot for one-time or to be persistent.

Spot fleets will try to meet the target capacity with the price constraints, based on strategies:
1. lowestPrice
2. diversified
3. capacityOptimized
4. priceCapacityOptimized
